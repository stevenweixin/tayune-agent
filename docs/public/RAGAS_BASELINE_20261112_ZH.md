### 指标具体测的是什么

- Faithfulness检查拆出的回答声明能否被实际上下文支持，不保证来源真实或任务完成。
- AnswerRelevancy从回答反向生成3个问题，用BGE-M3计算相似度并处理noncommittal标记。
  它不是人工判断“答对”的概率，也不能和换了Embedding的分数直接横向比较。
- ContextPrecision使用RAGAS带参考答案的平均精度算法，不是简单的相关片段占比。
  若相关证据排最前、噪声在后，AP仍可能很高；1.0不代表没有无关召回。
- ContextRecall统计参考答案声明被上下文支持的比例，**不是人工相关chunk标签下的Recall@K**。

上下文是当时模型可见的知识片段/商品证据组，按工具返回顺序保留重叠与重复；
每组为原始标题加evidence_units，不补全文、不重新检索、不把引用链接冒充证据。
因此这里测的是工具证据覆盖与排列，不是纯向量检索或Reranker单组件的独立得分。
参考答案的细粒度、替代配方和方法标签会影响覆盖率，仍需独立审核草稿口径。
指标定义见[RAGAS Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)、
[Answer Relevancy](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/answer_relevance/)、
[Context Precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/)、
[Context Recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/)。

## 典型失败与评审限制

| 案例 | 观察 | 说明 |
| --- | --- | --- |
| 白茶怎么泡 | 两条Faithfulness均1.0；原回答将杯泡比例/分钟与工夫泡秒数组合或并列 | 分句都能找到来源，但组合缺少同一方法的条件约束，不能据1.0判答对 |
| 隐私怎么联系 | 4路历史回答忠实度1.0、ContextRecall0 | 引用了安全/儿童/政策入口等内容，却没有召回并回答实际邮箱 |
| 菊花茶是否等于绿茶 | 忠实度均1.0；ContextPrecision均0 | 原文引用和商品价格不能代替清晰的类别对比；不同指标须结合逐题证据解释 |
| 茉莉花是否含咖啡因 | 单路返回兜底，4路引用茉莉花描述及单丛咖啡因文字 | 另一种茶的资料不能充当茉莉花依据；应明确资料缺失，不以无关原文凑答 |
| 那款茶怎么杯泡 | 上轮两次都未建立30美元以内茶品，追问仍选择了新产品；忠实度均1.0 | 有来源不等于指代正确；参考型指标N/A，需按多轮任务契约另行核验 |

还发现评审自身的局限：单路茉莉花两条兜底的Faithfulness都为0。
原始评审把“请稍后重试/联系店铺”等兜底语句拆成事实声明，再以检索资料没有这些话判0。
**这不等于系统编造了茶叶事实。** 原始0分保留，没有为了抬分删除兜底；应把安全拒答/服务降级单独评估。
同样，反向问题相似度对长答案和多轮投影的解释有限，本轮没有计算Answer Correctness或原生多轮Agent Goal Accuracy。
