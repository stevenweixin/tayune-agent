# TAYUNE-Agent：分层并发控制

更新时间：2026-11-02。正式代码已替换全局单请求锁；本次未重启8011生产进程，代码同步不等于部署。

## 目标与本轮范围

目标是面向C端的并发服务：不同用户的网络等待可以重叠，同一会话和稀缺推理资源分别保护。
本机阶段先采用单进程、有界准入与CPU排队，不通过无限排队、无限线程或取消预算换取表面吞吐。
这不是分布式高并发平台已经完成的声明。

## 原问题

旧Service用一个全局执行锁覆盖分类、检索、模型网络等待和会话保存。
任意用户正在回答时，其他用户立即429，空闲CPU也无法接收新的分类任务。
单独移除该锁又会触发CPUWorker忙时拒绝；前一轮真实依赖实验中8次请求有6次降级。

## 正式实现

| 层级 | 当前行为 | 保护什么 |
| --- | --- | --- |
| 聊天/任务恢复准入 | 默认最多4个执行，名额已满立即拒绝，不建立聊天等待队列 | 供应商调用和总体在途工作量 |
| 同会话所有权 | 聊天、恢复、记忆修改和删除共用会话占用检查 | 防止旧历史快照覆盖新状态 |
| CPU队列 | 最多16个待处理调用，排队加执行35秒，实际推理仍一次一个 | 分类、Embedding、检索/精排共享资源 |
| 知识工具 | 正式Runtime按聊天容量的2倍设待处理上限，默认8，内部串行 | 不把多路知识请求无限堆积 |
| 工具网关 | 继续最多2路工具执行，详情依赖已查到的商品ID | 外部读取及业务依赖 |
| 数据库 | 请求登记、日计数保持同一SQLite事务，幂等约束不变 | 防止重复登记、重复扣次 |

`RequestCoordinator`在同一事件循环中完成无await的检查和登记；读取会话历史之前先占用所有者。
它是单进程控制器，不是跨进程锁。网络调用等待期间，其他会话仍可使用剩余执行名额。

正常重放已保存的幂等结果不占新的聊天执行名额、不再次调用模型；同会话仍有在途任务时，
重复提交立即拒绝，不启动第二份计算。证据版本及60秒有效期检查照旧。

记忆修改只拒绝自身会话繁忙，不再因为其他顾客正在聊天就阻止修改。管理路由的本机限制及Bearer所有权检查未放宽。
取消必须属于该会话，且不会取消其他人的任务；取消后要等子任务退出才释放会话名额。
恢复任务不能绕过容量或同会话保护；主动取消恢复任务时返回正常的取消结果，HTTP调用者自身取消则继续传播取消。

CPUQueue保留底层CPUWorker：协程取消/超时不代表工作线程停止。
后续CPU请求必须等待残留线程真正结束；排队中已取消的请求不会在稍后偷偷开始执行。
队列关闭后拒绝新工作。CPU日志只包含任务ID、阶段、排队和执行等待耗时，不记录问题、参数或会话Token。

## 配置与部署

```dotenv
TAYUNE_MAX_CONCURRENT_CHATS=4
```

未填写时默认4，启动校验范围1–32。范围只是配置保护，不表示已经验证32路容量。
Runtime读取该配置，创建Service时使用同一数值；修改后需要重启应用生效。
本轮只更新`.env.example`，没有修改真实`.env`、模型名、日额度、IP限频或8秒会话间隔。

本轮也没有改插件、Tunnel、Milvus数据或课堂环境，没有进行付费问答。
当前8011进程没有被自动重启，所以不能说线上已经切换为4路。

仍须单进程启动。SQLite任务启动恢复逻辑和进程内所有权尚未适配多worker；不能直接把Uvicorn worker增加后共享同一数据库。

- 19条隔离HTTP权限、限流、幂等和故障契约通过。

  所有模型角色和商品接口仍替换为固定样例，8次模拟模型调用、0次付费调用。
- 两组均观察到4个实际在途聊天；第5个会话和同会话重复提交429，拒绝不扣日次数。
  自身繁忙时记忆修改409，其他会话修改200；完成历史分离，幂等重放不增加调用，最终槽位/所有者释放。
- 新单元检查覆盖并发请求的ContextVar用量隔离、额度事务、同会话重复、恢复争用、取消恢复、
  HTTP调用者取消、程序错误清理、CPU队列满、等待超时和残留线程。

## 后续扩展边界

1. 新代码重启加载后，另行授权真实模型混合负载和长时间稳态测试，校准并发/延时/成本目标。
2. 流量增长时，将CPU推理资源独立部署或扩充经过测试的工作池，而不是取消排队上限。
3. 多实例之前引入共享会话/任务存储、原子额度与跨实例会话调度，重写“启动时恢复全部running”的假设。
4. 再按业务时效评估公开知识缓存、供应商配额和自动扩缩容，保留拒绝、超时和降级。

## 面试口述

“我的目标是C端并发服务，不是所有用户共用一把大锁。现在正式实现允许不同会话有限并发，
同一会话保持串行，CPU推理单独有界排队。网络等待可以重叠，CPU不会无限叠加。
本机默认4路只是当前资源保护配置，并不是系统的永久上限；更高容量需要真实混合负载验证。
我已补齐记忆管理、取消、恢复和幂等的并发检查，但目前仍是单进程，分布式协调属于后续工作。”
